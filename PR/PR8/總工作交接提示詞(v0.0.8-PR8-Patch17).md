## Invariants / known risks
- Only the current durable dirty revision may write through Hub.
- A verified journal checkpoint supplies the bytes; never accept
  arbitrary editable text in low-level writer.
- SHA-256 source-region hash and file size/mtime guard against
  stale target content before write.
- Writer uses exclusive file stream, 64 KiB piecewise copying,
  then readback of source-chunk SHA-256 and replacement bytes.
Read source hashes before writer close, since old File Blob handles
may become unreadable after the browser swaps the underlying file.
- Checkpoint is deleted by exact revision/checksum CAS only after
  successful readback; a failed step leaves journal and dirty state.
- Browser file writer does NOT guarantee universal atomic OS swap,
  no guarantee against arbitrary external OS writes during save.
- FileDocument and visible UI remain unchanged; no full PR8 acceptance.
- Real large-file performance and actual file access permission E2E
  still need testing; no background work is scheduled.
