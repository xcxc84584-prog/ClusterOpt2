## Patch22–24 and Fix1 implementation
- DocumentSliceContract v1 and Workspace.sliceManifest UserAPI/Req/Rep.
- Explicit legacy-compatibility for small documents and virtual-page
  for large files. The legacy full-buffer renderer is not migrated.
- Per-document viewport owner protection in SliceRegistry; demotion
  respects document identity and visible/dirty slice guards.
- Identical viewport plans avoid repeat reads when resident slices remain.
- A skipped preload is not reread until viewport or budget changes.
- SliceLoader.loadBatch overlaps at most four independent Blob reads,
  commits in order through HubUnit and returns FINAL resident slices.
- A preloaded request never downgrades a full-resident slice.
- VTE/Node tests include multi-document budget, repeated reads, memory
  pressure, bounded 5 GiB synthetic seek and metadata-only large opens.
- Updated Plan/ArcD and Patch24-Fix1 record EventChains and limits.

## Must not claim
- The small-document editing backend is not universally sliced.
- Parallel Blob I/O is NOT parallel Worker CPU processing.
- Synthetic 5 GiB Blob tests are NOT real disk 5 GiB stress tests.
- Windows read/write permissions, multi-tab file locks, crash and
  interrupted Save/Recovery still need actual user/browser acceptance.
- Do not mark PR8 PASS merely because automated CI passes.

## OCDA invariant
Object = EHU/Log + Request + Response + UserAPI + AgentAPI +
Property + Program.
HubUnit is sole cross-object route; URU dynamic, EDPMU global,
OMU retains EHU and failures, relation code 00/10/01/11.
No SendTo(), machine-specific absolute paths or embedded credentials.
