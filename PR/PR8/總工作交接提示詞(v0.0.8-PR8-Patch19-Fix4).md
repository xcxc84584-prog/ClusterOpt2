  UserAPI, AgentAPI, Property and Program declared.

- LinkCore=HubUnit/OMU/EDPMU/URU, ephemeral dynamic registration.

  published only via LinkCore.

## Source and behavior
- Original ClusterOpt reference:
  Program/src/fmc/virtual-file-session.js and
  Program/src/fmc/storage-progress-tracker.js.
- New: Implementation/property/SliceBatchWritePolicy.js
- New: Implementation/object/SliceBatchWritebackUnit.js
- Modified: VirtualFileDocument, SliceEditTransaction, FileWorkspace,
  LinkCore, existing UI and regression tests.
- Dirty page Map retains each source-range's Piece Tree, text,
  original source hash and MVCC journal revision across navigation.
- Page LF index includes earlier unsaved edit line deltas.
- Recovery snapshot stores multiple page references, not text.
- Save composes a validated ordered list of all dirty page ranges
  into one FileSystemWritableFileStream operation.
- Byte-neutral edits: keepExistingData:true with positioned writes.
  Length-changing: unchanged Blob slices copied natively.
- All modified regions and final length verified; unchanged disk
  regions are trusted to browser/OS copy, NOT cryptographically
  reread after each Save.
- Existing asynchronous Save and per-document progress remain;
  cancellation before close retains dirty journal and disk source.
- Before batch Save, hidden pending recovery pages are lazily
  hydrated from durable journals with original byte-range hashes;
  no hidden unsaved page is omitted.
- Up to 64 registered pages via SliceTransactionPolicy; hitting
  cap must return EHU413, never evict a dirty page.
